## 2026-08-20：第二版语义 Grounding 与决策流水线回归

本次在不修改 Mininet/OVS 执行动作的前提下，完成 Semantic Intent、服务端版本化 SLA Grounding、受控候选生成、确定性评价与可解释稳定排序的第二版重构。验证覆盖：

- `service` 缺省映射、显式服务错配、语义字段枚举/长度/数量和未知字段拒绝。
- 编译阶段服务端重新 Grounding，客户端伪造 SLA 版本、派生约束、动作或命令字段被拒绝。
- 显式约束与 SLA 派生约束冲突时阻断并保留双方来源；车辆控制和导航没有可靠 SLA 数值时不补造阈值。

- 没有学习模型时，动态 KPI 逐项返回 `not_available`，不参与效用数值评分，也不冒充 Mininet 实测。

## 2026-08-14：`combined` 初次实测

在具备 root 权限的本机，通过页面完成“综合保障”策略的解析、编译、人工确认下发和指标展示。实测结果如下：

| 指标 | 基线 | 策略后 |
|---|---:|---:|
| 紧急业务 P95 时延 | 24.7 ms | 19.9 ms |
| emergency 吞吐 | 4.45 Mbps | 5.25 Mbps |
| control 吞吐 | 2.80 Mbps | 3.16 Mbps |
| navigation 吞吐 | 2.74 Mbps | 2.11 Mbps |
| video 吞吐 | 17.20 Mbps | 7.78 Mbps |
| emergency 丢包 | 0% | 0% |
| control 丢包 | 1.5% | 0% |
| navigation 丢包 | 9.2% | 0% |
| video 丢包 | 1.3% | 50% |

该结果确认了临时 Mininet 拓扑、OpenFlow 转发和 OVS QoS 队列能够成功运行：`combined` 将视频压至接近 8 Mbps 的模板上限，同时改善了紧急业务的时延和吞吐。视频丢包上升是 18 Mbps 背景发送速率被固定限至 8 Mbps 左右的预期结果。

## 2026-08-14：计量器修复后的最终复测

| navigation 吞吐 | 2.96 Mbps | 2.11 Mbps |
| video 吞吐 | 17.00 Mbps | 7.78 Mbps |
| emergency 丢包 | 0% | 0% |
| control 丢包 | 16.0% | 0% |
| navigation 丢包 | 1.4% | 0% |
| video 丢包 | 2.4% | 53.0% |
| 低时延路径利用率 | 73.78% | 11.56% |
| 高容量路径利用率 | 0% | 13.83% |

本次满足最终验收：视频吞吐 7.78 Mbps，低于 8.5 Mbps 的执行容差；高容量路径利用率从 0% 升至 13.83%，说明视频已迁移；紧急业务 P95 时延下降 4.3 ms，吞吐提升至 5.26 Mbps。视频高丢包是 18 Mbps 压力流受 8 Mbps 丢弃型计量器限制的预期结果。

补充风险：策略模板中的 20 ms 是编译期能力声明，本次单次 P95 为 20.8 ms，未作为运行期硬失败阈值。若后续要把它升级为严格 SLA，需要增加多次采样、置信区间和针对时延的准入/回退逻辑；这不属于当前初始 Demo 范围。

## 2026-08-14：突发窗口复测与修复

后续一次运行测得视频策略后吞吐 8.72 Mbps，超过 8.5 Mbps 判定阈值，执行器按设计返回 `policy_effectiveness_failed`，没有伪造成功结果。原因是此前计量器未显式指定 burst，OVS 可自行选择较大的默认突发。当前代码已为 8 Mbps 计量器显式设置 64 kbps burst；需再次 root 复测后才能将本次结果更新为最终验收。
